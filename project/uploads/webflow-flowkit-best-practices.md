## 1. Decision rules

### Which class system?

| Situation | Use |
|---|---|
| Project generated by Webflow AI or installs from Webflow Libraries | **Flowkit v2** |
| Existing Client-First project (most Finsweet/community builds) | **Client-First** |
| New project from scratch, choose freely | Pick one and stick with it. Flowkit v2 is the safer default in 2026 because it's now native to Webflow. |
| Migrating or auditing | Identify the existing system first by inspecting class names. Don't mix. |

**How to identify in a live project:**
- Flowkit: classes use `_` between component parts (`card_body`), modifiers prefixed `is-`, `on-`, `gap-`, `ix-`, t-shirt sizing (`xsmall`–`xxlarge`).
- Client-First: utility classes use hyphens only (`padding-global`, `text-color-primary`), custom classes use underscores as folder dividers (`home-header_texture`), combo classes prefixed `is-`.

### When to add custom code vs use native features

Default to native Webflow first. Only add custom code when:
1. Webflow's native features genuinely can't achieve the result.
2. A specific performance or accessibility requirement demands it.
3. You're integrating a third-party service that has no native option.

Custom code adds maintenance burden and breaks accessibility/SEO if done poorly. **Pronto Coffee context**: prefer auditing and removing custom code that duplicates native Webflow capability.

## 2. Core philosophy

These principles hold regardless of class system:

1. **Name by purpose, not appearance.** `form-button` not `blue-button`. Colour can change; function rarely does.
2. **Use the smallest reasonable HTML structure.** Don't add a wrapper div unless it does something.
3. **Set typography on tags first, then override with classes.** Style `All H1 Headings`, `Body`, `Paragraph` before adding custom heading classes. This way unstyled content still looks correct.
4. **rem-based sizing for accessibility.** 16px = 1rem. Lets browser zoom and font-size settings work properly.
5. **One H1 per page.** Visually style with classes if needed (e.g. apply `heading-style-h2` to an H1 tag), but keep the semantic tag.
6. **Reuse over recreate.** Components, variables, and global classes beat ad-hoc styling.
7. **Build the style guide page first.** It catches inconsistencies before they spread across the site.

## 3. Flowkit v2

Flowkit is Webflow's official modular CSS framework, used by Webflow AI-generated sites and available in the Webflow Library. It is the recommended default for new builds in 2026.

### 3.1 Naming convention

Flowkit uses **hyphens** and **underscores** with specific roles:

**Hyphens (`-`) are for:**
- Connecting multiple words inside a class name: `rich-text`, `text-align_center`, `background_primary`
- Combo class modifiers: `is-secondary`, `on-inverse`, `gap-small`
- Responsive modifier prefixes on combo classes: `tablet-vertical`, `mobile-2-col`

**Underscores (`_`) are for:**
- Separating a component from its parts: `card_body`, `nav_logo`, `footer_link`
- Connecting a utility property with its value: `margin-top_small`, `width_40percent`, `z-index_2`
- Adding a breakpoint postfix to a utility: `text-align_center_mobile`, `width_100percent_mobile-l`

**Critical distinction**: `_mobile` (postfix) scopes a utility to that breakpoint only. `mobile-` (prefix on a combo class) overrides a base style at that breakpoint.

- `text-align_center_mobile` → text is centred **only on mobile**.
- `text-align_center mobile-align-left` → text is centred by default, but becomes left-aligned on mobile.

### 3.2 Four class types

#### Component classes
Define standalone UI elements with structure and (sometimes) nested parts.

**Pattern**: `component` or `component_part`

| Class | Purpose |
|---|---|
| `card` | Flexible content container with shadow and padding |
| `card_body` | The body part of a card |
| `nav` | Main website navigation bar |
| `nav_logo`, `nav_link`, `nav_links` | Nested nav parts |
| `button` | Reusable clickable element |
| `footer`, `footer_link` | Site footer + nested link |

#### Utility classes
Single-purpose styling. Apply to any element.

**Pattern**: `property_value`

| Class | Purpose |
|---|---|
| `margin-top_medium` | Applies medium top margin |
| `padding-horizontal_large` | Large padding both sides |
| `z-index_2` | Sets z-index to 2 |
| `background_primary` | Sets background to primary colour |
| `text-align_center` | Centres text |
| `display_inline-block` | Sets display |

Utility classes may apply multiple CSS properties but always serve one visual purpose.

#### Combo classes
Modifiers that change appearance or behaviour of a base component. Always follow a main class.

| Prefix | Purpose |
|---|---|
| `is-` | Component variant (style/state) |
| `on-` | Surface context (which background it sits on) |
| `gap-` | Spacing in flex/grid containers |
| `ix-` | Interaction/animation hook |
| `tablet-`, `mobile-l-`, `mobile-` | Responsive override |

**Examples:**
- `button is-secondary` — secondary-style button
- `text-link on-accent-primary` — text link adapted for accent-primary background
- `flex_horizontal gap-medium` — flex container with medium gap
- `section is-secondary` — section with adjusted background and text colours

#### Responsive modifiers
Apply styles at specific breakpoints. Postfixes:
- `_tablet` — tablets
- `_mobile-l` — mobile landscape
- `_mobile` — mobile portrait

Examples: `width_100percent_tablet`, `text-align_center_mobile`.

### 3.3 T-shirt sizing scale

Applies consistently across spacing, borders, text, icons, radius:

`xxsmall` → `xsmall` → `small` → `medium` → `large` → `xlarge` → `xxlarge`

Examples: `icon is-xxsmall`, `radius_small`, `text_medium`, `gap_large`, `padding-top_xxlarge`.

### 3.4 Surface modifiers

Used across `button`, `text`, `nav`, `icon`, `card` to adapt styling to the background:

| Surface | Example combo |
|---|---|
| Accent Primary | `button is-secondary on-accent-primary` |
| Accent Secondary | `text-link on-accent-secondary` |
| Accent Tertiary | `icon on-accent-tertiary` |
| Primary | `card-link on-primary` |
| Secondary | `card-link on-secondary` |
| Inverse | `button on-inverse` |

### 3.5 Animation modifiers (`ix_` prefix)

Hooks for Webflow Interactions, **not** for styling. Examples:
- `ix_section-scroll-in` — scroll-based entrance
- `ix_image-zoom-hover` — hover scale
- `ix_nav-slide-out` — mobile menu animation
- `ix_button-tap` — tap/click animation
- `ix_card-flip` — flip animation

### 3.6 Page structure (Flowkit v2)

Semantic, component-based:

```
Body (All Pages)
└── nav (tag: nav, class: nav)
└── section (tag: section, class: section)
    └── container (tag: div, class: container)
        └── [layout: grid, flex, card, etc.]
└── footer (tag: footer, class: footer)
```

**Section** is the core layout block. Always set tag to `section`. The base class includes default vertical padding.

Section variants via combo classes:
- `section is-secondary`, `section is-accent-primary`, `section is-accent-secondary`, `section is-accent-tertiary`, `section is-inverse`

Section padding adjustments:

| Utility | Effect |
|---|---|
| `padding_none` | Removes top & bottom |
| `padding-vertical_small` | Vertical small |
| `padding-top_none`, `padding-bottom_small` | Fine-tuned |

**Container** centres content with max-width and horizontal padding:

| Class | Effect |
|---|---|
| `container` | Default max-width |
| `container is-full-width` | Edge-to-edge |
| `container is-large` | Larger max |
| `container is-small` | Narrow max |

Use `padding-horizontal_none` to remove side padding.

**Navigation** uses `<nav>` tag + `nav` class. Surface variants: `nav is-accent-primary`, `nav is-inverse`, etc.

**Footer** uses `<footer>` tag + `footer` class. Surface variants follow the same pattern. Each footer variant has a matching `footer_link on-inverse` (or `on-accent-primary`, etc.) for the links inside.

### 3.7 Components available in Flowkit v2

**Interactive**: Buttons, Tag, Dropdown, Accordion
**Content display**: Images, Cards, Rich Text, Divider
**Forms**: Forms (inputs, labels, layouts)
**Navigation**: Tabs, Slider

Button class naming: `button is-secondary is-small on-accent-primary` (combo classes stack: variant + size + surface).

### 3.8 Variables (design tokens)

Three core categories:

| Category | Holds |
|---|---|
| **Colors** | Foundational palette |
| **Sizes** | Spacing, radius, sizing scales, layout metrics |
| **Typography** | Font families, base sizes, type styles |

Update once, propagates everywhere. Use semantic names tied to the design system, not raw values.

## 4. Client-First

Built by Finsweet, widely used across the Webflow community. Goal: a project any developer, client, or non-technical person can read and understand by class names alone.

### 4.1 Naming principle

> A Webflow developer, client, or any person should understand what a class is doing based on the class name, even if they've never used Client-First.

- No abbreviations, no shorthand.
- Describe purpose, not appearance.
- Use the `_` character to define a "custom class" and to act as a virtual folder divider.

### 4.2 Class types

#### Custom classes — use `_` in the name
For something specific and visual on the page. The `_` divides "folders" of related classes.

Examples: `about-team_component`, `footer_column`, `clients-slider_arrow`, `nav_link`, `home-header_texture`.

Form structure example:
- `form_component`
- `form_wrapper`
- `form_block`
- `form_label`
- `form_input`
- `form_submit`

#### Utility classes — no `_` in the name
For a specific CSS style combination that applies across the project.

Examples: `padding-global`, `max-width-small`, `margin-large`, `text-color-secondary`, `background-color-dark`, `display-none`.

#### Global classes
Either a utility (always global) or a recurring custom class like `header_content` used across the site.

#### Combo classes — `is-` prefix
A variant added on top of a base class. Only works when stacked with the base.

Example: `button` (base) + `is-brand` → only takes effect when combined. `is-brand` alone does nothing.

### 4.3 Core structure (Client-First)

Six classes form the base of every Client-First page:

```
page-wrapper
└── main-wrapper (tag: <main>)
    └── section_[identifier] (tag: <section>)
        └── padding-global
            └── container-[size]
                └── [content / components]
```

Plus `padding-section-[size]` typically combined with `padding-global` on the same div for vertical spacing.

**What each does:**

| Class | Role |
|---|---|
| `page-wrapper` | Outermost parent. Lets you avoid styling `<body>` directly. Apply page-level rules like `overflow: hidden` here. |
| `main-wrapper` | `<main>` tag. Holds page main content. Excludes nav and footer. Accessibility best practice. |
| `section_[identifier]` | `<section>` tag. One per page section. Makes Navigator usable, supports anchor scrolling. Avoid heavy styling; use a global modifier like `section-style-dark` for variants. |
| `padding-global` | Site-wide left/right padding. **Only** `padding-left` and `padding-right` properties — don't add other styles. |
| `container-[size]` | `margin-left/right: auto`, `width: 100%`, `max-width: [small/medium/large]`. |
| `padding-section-[size]` | Top/bottom padding for sections. Comes in small/medium/large by default. |

**Why decouple padding from container?** You can apply `padding-global` outside, inside, or both relative to `container-large`, depending on the layout. If padding is baked into the container, you lose that flexibility.

### 4.4 Typography strategy

- Style HTML tags first: `All H1 Headings`, `All H2 Headings`, …, `Body`, `All Paragraphs`.
- **Only add a class when the element customises the default.** No class on a default-styled H1.
- Utility class families:
  - `heading-style-[h#]` — apply visual style of an h2 to an h1 tag (preserves SEO)
  - `text-weight-[weight]`
  - `text-size-[size]`
  - `text-style-[css-property]`
  - `text-color-[identifier]`
  - `text-align-[alignment]`

### 4.5 Spacing strategy

Two complementary approaches:

**Utility approach (preferred for most spacing):**

1. **Spacing block** — empty div between two siblings: `padding-bottom` + `padding-medium` creates space between siblings.
2. **Spacing wrapper** — div wrapping a child: `margin-bottom` + `margin-medium`. Wrapper creates space between itself and its sibling.

**Custom class approach:**

1. **Custom class on element** — when a specific element needs unique spacing the utility system can't reach (e.g. `faq_title` with `margin-bottom: 0.75rem`).
2. **CSS Grid** — for lists of children, set grid on the parent and let `gap` handle spacing for all children at once.

### 4.6 Folders (via Finsweet Extension)

`_` creates virtual folders in the class panel:

- `blog_header_graphic` → blog folder → header folder → graphic
- `text-color-primary` → Utility classes folder → text- folder → color- folder → primary

Any class **without** `_` lands in the Utility folder automatically. Each `_` creates another level.

### 4.7 rem and sizing

- Client-First uses rem throughout. 16px = 1rem (browser default).
- All sizes are multiples of 16: `96px / 16 = 6rem`, `32px / 16 = 2rem`, `4px / 16 = 0.25rem`.
- Rem respects browser font-size settings and zoom — significant accessibility win.

## 5. Semantic HTML and structure

Use semantic tags. They make sites more accessible (screen readers and assistive tech depend on them) and improve SEO (search engines parse structure from them).

### 5.1 Tag reference

| Tag | Use for |
|---|---|
| `<header>` | Top of document or section. Most commonly wraps navbar. Can appear multiple times on a page. Cannot be inside `<footer>`, `<address>`, or another `<header>`. |
| `<nav>` | Navigation link clusters: navbar, sidebar, table of contents, footer links, breadcrumbs. |
| `<main>` | Main content of the page. Unique to that page. **Excludes** nav, footer, sidebars, cookie banners, and other repeating content. |
| `<section>` | A thematic section of the page. Should almost always have a heading. Use one per logical block. |
| `<article>` | Self-contained, independently distributable content: blog post, forum post, product card, magazine entry, comment, interactive widget. Not only for blog posts. |
| `<aside>` | Content tangential to the main flow: related links, sidebars, ads, table of contents. Place inside the section it relates to. |
| `<footer>` | Footer of the page **or** the nearest sectioning parent. An article can have its own footer. |
| `<address>` | Contact info for the author/owner. Refers to article if inside `<article>`; to document if outside. |
| `<figure>` | Self-contained content like illustrations or code blocks. Removing it shouldn't break flow. |
| `<h1>` – `<h6>` | Heading levels. **One `<h1>` per page** as the page title. Don't skip levels. |

### 5.2 Heading rules

- Exactly one `<h1>` per page. It should describe what the page is about.
- Sub-topics use `<h2>`. Sub-sub-topics use `<h3>`. And so on.
- Never skip levels (no jumping h1 → h3).
- Don't use heading tags purely for visual size. Use the correct tag, then style it with a class. Example in Client-First: H1 tag + `heading-style-h2` class for a smaller H1.

### 5.3 How to set tags in Webflow

Element selected → Settings panel (D) → Tag dropdown → choose the appropriate semantic tag. Default is `<div>`; change it whenever the content has semantic meaning.

## 6. Accessibility

Target: **WCAG 2.1 or 2.2 Level AA**. This is the practical standard for most jurisdictions in 2026 and what the Webflow Audit panel checks against.

### 6.1 Quick checklist

- [ ] One `<h1>` per page; heading hierarchy is logical and unskipped.
- [ ] Landmarks set: `<header>`, `<nav>`, `<main>`, `<footer>`. Skip link present and working.
- [ ] All meaningful images have descriptive alt text. Decorative images marked decorative (`alt=""`).
- [ ] Text contrast ≥ **4.5:1** for normal text, ≥ **3:1** for large text (≥ 18pt or 14pt bold).
- [ ] Borders on actionable elements (inputs, radios, checkboxes) ≥ 3:1 contrast against their background.
- [ ] Icons that convey information ≥ 3:1 contrast against background.
- [ ] All interactive elements have a visible focus state. Tab order is logical.
- [ ] No keyboard traps. Modals and menus close with Esc and restore focus.
- [ ] Forms have visible labels, inline error messages, and helpful instructions.
- [ ] Motion respects `prefers-reduced-motion`. No autoplaying audio. Animations stay below ~10% of central visual field.
- [ ] `html lang` attribute is set (e.g. `lang="en-NZ"`).
- [ ] Link text is descriptive (not "click here", "read more"). Same goes for buttons.
- [ ] Site works zoomed to 200%+ without content overlap or loss.
- [ ] Tap targets ≥ 44×44px on mobile.

### 6.2 Alt text guidance

- Describe purpose, not appearance: `"blue 'Sign Up' button"` not `"blue button"`.
- Aim for ≤ 125 characters.
- Don't start with "Image of" or "Photo of" — screen readers already announce that.
- Decorative images: leave alt blank (`alt=""`) so screen readers skip them.
- Functional images (icon-only buttons): describe the action, not the visual ("Search" not "magnifying glass icon").
- For CMS images: ensure the collection has an alt-text field and bind it per item.

### 6.3 Webflow's built-in accessibility tools

| Tool | Where | Use for |
|---|---|---|
| **Audit panel** | Lower-left of Designer | Missing alt text, empty links, heading structure issues, contrast warnings |
| **Color contrast checker** | Style panel | Live WCAG AA/AAA pass/fail on text colours |
| **Vision Preview** | Designer | Simulate colour blindness, blurred vision |
| **Text Zoom Preview** | Designer | Verify layout holds at 200%+ text zoom |

### 6.4 External audit tools (do these too)

- **WAVE** (wave.webaim.org) — paste public URL, get inline error markers.
- **Google Lighthouse** — Chrome DevTools → Lighthouse → Accessibility report.
- **Axe DevTools** — more granular WCAG violations.
- **WebAIM Contrast Checker** — colour ratio sanity check.

### 6.5 Manual tests every site needs

1. **Tab through the whole site**. Every link, button, modal, and input should be reachable, in a logical order, with a clear visible focus ring.
2. **Screen reader test** — VoiceOver (Mac), NVDA (Windows free), or JAWS. Try completing the primary user flow blindfolded.
3. **Zoom to 200%+** — check no content overlaps or is cut off.
4. **Mobile tap target check** — ≥ 44×44px for buttons and links.

### 6.6 Common Webflow accessibility mistakes

- Using `<div>` everywhere instead of semantic tags. Screen readers can't navigate divs.
- Multiple `<h1>` tags on one page.
- Styled `<p>` tags that look like headings (don't use paragraph tags as visual headings).
- Missing or non-descriptive link text.
- Low-contrast text over background images or gradients.
- Forms without labels (placeholder text is **not** a label).
- Motion that triggers vestibular disorders or seizures — keep durations under 300ms and respect reduced-motion preference.

## 7. SEO checklist

Webflow generates clean semantic HTML and gives full control over meta tags, but it won't do SEO automatically. Setup is per-page.

### 7.1 Design and build phase

- [ ] Plan a clear site structure — keep important pages ≤ 3 clicks from homepage.
- [ ] Responsive on desktop, tablet, and mobile. Test all breakpoints.
- [ ] Keyword research done; primary keyword per page identified.
- [ ] One `<h1>` per page containing the primary keyword.
- [ ] H2/H3 hierarchy logical, includes related keywords naturally.
- [ ] Semantic HTML5 tags set on Sections, Headers, Nav, Main, Footer.
- [ ] URL slugs short (< 75 chars), descriptive, hyphenated, consistent.
- [ ] **Meta title** set per page (< 60 chars).
- [ ] **Meta description** set per page (< 160 chars).
- [ ] **Open Graph** image, title, description set per page (the home OG should differ from pricing OG, etc.).
- [ ] Alt text on every meaningful image.
- [ ] SSL enabled in Site Settings.
- [ ] Content is original, E-E-A-T quality (Experience, Expertise, Authority, Trustworthiness).

### 7.2 Tracking and tools

- [ ] **Google Search Console** verified.
- [ ] **Google Analytics** (or Webflow Analyze) installed.
- [ ] **Google Tag Manager** installed if running multiple scripts.
- [ ] **Google Business Profile** set up for local businesses (relevant for NZ real estate, hospitality, etc.).

### 7.3 Pre-launch

- [ ] Sitemap submitted to Google Search Console (Webflow auto-generates one).
- [ ] **Disable indexing on the `.webflow.io` subdomain** to avoid duplicate content issues.
- [ ] Custom 404 page designed with helpful navigation back to the site.
- [ ] **Minify** CSS, JS, HTML in advanced publishing options.
- [ ] Images compressed (use Webflow's image conversion tool for AVIF/WebP).
- [ ] 301 redirects set for any changed URLs from a previous site.
- [ ] **Global canonical tag** set to avoid duplicate-content penalties.

### 7.4 Post-launch / ongoing

- [ ] Run monthly/quarterly site audits. Track Core Web Vitals (LCP, INP, CLS).
- [ ] Implement schema markup where relevant (Article, Product, LocalBusiness, FAQ).
- [ ] For multi-region sites: Webflow Localization for hreflang, localized URLs, HTML lang per locale.
- [ ] Consider Generative Engine Optimization (GEO) — clear structure, FAQs, and answer-friendly content help your site appear in AI overviews.
- [ ] A/B test headings, CTAs, formatting via Webflow Optimize.

### 7.5 Real-estate-specific notes (for Nichols | Polson & Co context)

- LocalBusiness schema with NAP (name, address, phone) consistent across site, Google Business Profile, and Harcourts directory.
- Listing pages: Product or RealEstateListing schema with price, location, agent.
- Agent pages: Person schema with `worksFor` linked to the agency.
- Suburb landing pages perform well — each suburb page needs unique meta, H1, and 300+ words of original content.

## 8. Design systems

### 8.1 Setup foundation

1. **Define goals**. Consistency? Speed? Multi-client reuse? Goals shape governance.
2. **Choose organisation method**. By layout (Hero, Footer), by function (Button, Card), or Atomic Design (Atoms → Molecules → Organisms).
3. **Document naming rules**. Once chosen, stick with them. Prefix utilities (e.g. `u-`) and combo classes (`is-`) consistently.
4. **Build a style guide page**. Source of truth. Lives in the site so you can preview live styles and test changes.
5. **Bake accessibility in from the start**. Heading levels, alt patterns, colour contrast meeting WCAG AA, keyboard navigation.

### 8.2 Variables (design tokens)

- Group into **collections** (broad: Primitives, Themes) and **groups** (related: Spacing, Typography, Components).
- Use **primitives** for raw values (`Blue 400`, `1rem`) and **semantics** for contextual use (`Card Background`, `Error Border`).
- Naming: `Typography / Heading / H1`, `Spacing / Section / XL`, etc.
- Start small — brand colours, font styles, base spacing — then expand.

### 8.3 Components

- Build them **before** the site if possible. Adding them later means refactoring.
- Start with what you'll reuse most: nav, footer, button, card, section header.
- Use **component properties** for content that changes per instance: headline text, image, button label, toggle visibility.
- Use **slots** for entire block swaps: hero subheading area, card content area.
- Use **style variants** for theme variations (light/dark, primary/secondary, sizes). Keep variants to 2–3 per component; don't proliferate.
- Group components clearly: "Sections", "Cards", "Utilities". Document each.

### 8.4 Templates

- Static page templates for repeating page types: case studies, landing pages, event pages.
- CMS Collection pages for dynamic content: blog posts, products, listings, team profiles.
- Bake your design system into both so consistency is automatic.

### 8.5 Shared libraries

- Webflow's Shared Libraries let you push components, variables, and assets across all sites in a workspace.
- Best practice: maintain a separate **style guide site** as the source library, then install that library into each project.
- Use Design Approvals when pushing updates. Communicate breaking changes before publishing.
- Maintain a changelog in your style guide.

### 8.6 Governance

- Define who can update the library. Restrict editing to a lead designer/dev.
- Run quarterly audits — remove unused styles, simplify spacing variables, refresh documentation.
- Keep a "Deprecated" folder for items being phased out, instead of deleting immediately.

## 9. Interactions and motion

### 9.1 Purpose-driven motion

- Animations should clarify, not decorate. Hover states confirm clickability; scroll-in reveals guide attention.
- Keep durations short (under 300ms) for snappy feel and good performance.
- Define a motion system: standard ease (e.g. `ease-out`), standard duration (e.g. 200ms), standard delay patterns.
- Document the motion system alongside visual styles. Reuse via components and interaction presets.

### 9.2 Accessibility constraints on motion

- Respect `prefers-reduced-motion`. Provide a no-motion fallback.
- No autoplaying audio.
- Avoid motion behind static text — depth mismatch can be triggering.
- Excessive motion = motion taking more than ~10% of the central visual field. Keep large-area animations subtle and slow.
- No flashing > 3 times per second (seizure risk).

### 9.3 Flowkit interaction hooks

Flowkit uses the `ix_` prefix as a binding hook between the class and Webflow Interactions. The class itself doesn't style; it identifies the element so the interaction can target it.

Common patterns:
- `ix_section-scroll-in`
- `ix_image-zoom-hover`
- `ix_button-tap`
- `ix_card-flip`
- `ix_nav-slide-out`

## 10. Webflow MCP tool usage rules

These apply specifically when Claude is working with the Webflow MCP tools (Pronto Coffee context, future client builds). Always call `webflow_guide_tool` first in a Webflow MCP session.

### 10.1 Core rules

- **Plan before calling**. Don't fire tools randomly.
- **Don't assume site_id**. If a tool requires it and it's not in context, ask.
- **Reuse existing styles**. Don't create new ones unless explicitly asked.
- **After creating an element, it's NOT auto-selected**. Use `element_tool > select_element` with the returned ID to inspect or modify it.
- **Data tools** = REST API. **Designer tools** = UI tools in the Designer canvas. Use the correct family.

### 10.2 Styles

- Create styles **first**, then apply them when creating elements.
- Use longhand CSS property names when defining style properties.
- Breakpoint behaviour:
  - `xxl` (1920px) — screens ≥ 1920px
  - `xl` (1440px) — screens ≥ 1440px
  - `large` (1280px) — screens ≥ 1280px
  - `main` — applies to all devices unless overridden
  - `medium` (tablet) — screens ≤ 991px
  - `small` (mobile landscape) — screens ≤ 767px
  - `tiny` (mobile portrait) — screens ≤ 478px

### 10.3 Elements

- Only `Container`, `Section`, `DivBlock`, and some DOM elements can have children.
- Only **component instances** (created via `component_builder`) can go inside slots. No regular elements in slots.
- To move an element: `element_tool > move_element` with `{ id, anchor_element_id, creation_position }`. Bindings and styles are preserved.
- To delete: `element_tool > remove_element` — destructive, can't be undone via tool.
- For DOM IDs: use `set_id` for static or bound values; `update_id_attribute` only handles statics. Do not include the `#` character.

### 10.4 Components and slots

- To open a component for editing: `de_component_tool > open_canvas` with a `component_id`.
- To enter in-context editing on an instance: `open_component_view` / `close_component_view`.
- To insert a Slot: `element_builder` with `type: "ComponentSlot"`, while inside the component's canvas.
- Unregistering a component is destructive — removes all instances. Confirm before calling.

### 10.5 Variants

- Base variant has reserved id `'base'`. It cannot be deleted but can be renamed.
- Variant styles override base styles on a per-variant, per-breakpoint, per-pseudo basis.
- New variants are NOT auto-selected after creation.

### 10.6 Variables

- Three storage shapes per variable value: `static_value`, `existing_variable_id` (alias), or `custom_value` (raw CSS like `calc(100vh - 60px)`).
- Style variable modes: apply a collection's mode to a style so variable lookups resolve through that mode.
- Workflow: `get_variable_collections` → `set_style_variable_mode` → `get_style_variable_modes` to verify.

### 10.7 WHTML builder (HTML/CSS import)

- HTML must have a single root element (no fragments).
- No `<style>` tags inside HTML — pass CSS via the `css` parameter.
- CSS rules: no `@keyframes`. Only valid Webflow breakpoint media queries:
  - Desktop default: no media query
  - Tablet: `@media screen and (max-width: 991px)`
  - Mobile landscape: `@media screen and (max-width: 767px)`
  - Mobile portrait: `@media screen and (max-width: 479px)`

### 10.8 Localization

- `data_localization_tool` writes to **secondary locales only**. The primary locale is read-only via this tool.
- Discover locale IDs: fetch site details via `data_sites_tool`.
- Typical flow: `data_sites_tool` (find locales) → `list_components` (find IDs) → `get_page_content` or `get_component_content` with `localeId` (see current state) → `update_static_content`/`update_component_content` to write translations.

## 11. Quick checklists

### Pre-launch checklist

- [ ] One H1 per page, hierarchy logical
- [ ] Semantic tags set: header, nav, main, section, article, aside, footer
- [ ] All meaningful images have alt text; decorative images marked decorative
- [ ] Meta title (< 60 chars) and meta description (< 160 chars) per page
- [ ] Open Graph image, title, description set per page
- [ ] URL slugs short, descriptive, hyphenated
- [ ] Custom 404 page designed
- [ ] Sitemap generated and submitted to Google Search Console
- [ ] `.webflow.io` subdomain indexing disabled
- [ ] Global canonical tag set
- [ ] SSL enabled
- [ ] Forms tested with real submissions; spam protection enabled
- [ ] All breakpoints checked (xxl, xl, large, main, medium, small, tiny)
- [ ] Webflow Audit panel run; zero critical issues
- [ ] WCAG contrast ratios pass (4.5:1 text, 3:1 large text and icons/borders)
- [ ] Tab navigation works end-to-end; focus rings visible
- [ ] 301 redirects mapped for any URL changes from previous site
- [ ] CSS, JS, HTML minified in advanced publishing options
- [ ] Images compressed (AVIF/WebP where appropriate)
- [ ] Google Search Console, Analytics, Tag Manager installed
- [ ] Custom domain connected, www/non-www handled consistently
- [ ] Style guide page exists in the project for reference

### Class-naming sanity check

Ask before saving a new class:
1. Does the name describe **purpose**, not appearance?
2. Would a non-technical client/teammate understand it?
3. Does it follow the project's existing system (Flowkit v2 OR Client-First — not both)?
4. Is it specific enough to be unique, general enough to be reusable?
5. If it's a combo, does it start with the agreed prefix (`is-`, `on-`, `gap-`, `ix-` for Flowkit; `is-` for Client-First)?

### Audit checklist for inheriting a project (e.g. Pronto)

- [ ] Identify the class system in use. Don't mix.
- [ ] Run Audit panel — fix critical issues first.
- [ ] Check for unused styles and components — flag for cleanup.
- [ ] Check for custom code — identify what's necessary vs replaceable with native.
- [ ] Verify all meta tags and OG tags per page.
- [ ] Test responsiveness on all breakpoints.
- [ ] Lighthouse audit — Performance, Accessibility, Best Practices, SEO scores.
- [ ] Confirm Webflow Library / Shared Library status if multiple sites are in scope.
- [ ] Document any inherited quirks or naming inconsistencies in a project notes doc.

### When something looks off in Webflow Designer

1. Check the breakpoint — styles cascade down from xxl/xl/large/main.
2. Check combo class stacking — base must come first.
3. Inspect element settings for tag mismatch.
4. Audit panel may have caught it already.
5. For interactions not firing: confirm the `ix_` (Flowkit) or relevant class is actually on the element, and the trigger is targeting that class.
